# Mudanças propostas

Crie uma subpasta por mudança antes de alterar comportamento aceito, por exemplo:

```text
openspec/changes/notificacoes-de-prazo/
  proposal.md
  tasks.md
  specs/
    weekly-agenda-and-study-plan/spec.md
```

Use um identificador curto, em minúsculas e com hífens. A proposta deve declarar problema, objetivo, escopo, não escopo, impacto em dados/segurança e critérios de aceite. Ao concluir a implementação, atualize o spec canônico em `../../specs/` e arquive a proposta.
